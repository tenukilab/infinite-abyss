# 決定事項・未実装・開発方針（v0.23）

> 2026-11-23時点。**実装済**と**構想**を混同しないための管理表。
> 企画の方向性はユーザーが決定し、AIは必要な仮数値を提案・実装する。仮値は後で調整可能。

## 0. 開発ロードマップ（案）

**現在地**　セーブ保全の修正は公開済み。図鑑IDの衝突も修正済み。PRに回帰テストを導入した。次は残る仕様と実装のずれを整理する。[公開記録](https://github.com/tenukilab/infinite-abyss/actions/runs/45203640126)

| 順序 | 取り組むこと | 完了の目安 |
| --- | --- | --- |
| 1 | **図鑑IDの衝突を解消する**。第2層・第15層の「青燐の骸骨兵」に別IDを割り当てる。 | [実装済] 256件のIDは一意。旧合算記録だけを初期化し、以後の戦績を階層別に保存する。[図鑑仕様](encyclopedia.md) |
| 2 | **PRで回帰テストを実行する**。既存のセーブ回帰テストと図鑑の移行テストをGitHub Actionsで走らせる。 | [実装済] 旧v5の読み込み、JSON復元、破損データの保全、図鑑移行をPRの結果から確認できる。[テスト手順](technical-notes.md#6-回帰テストの最低ライン) |
| 3 | **仕様と実装のずれを整理する**。旧版の職数・Lv上限を更新し、転職時のHPは意図を確認する。 | 回帰テストで転職時の能力値・装備、150ターン撤退、自動周回停止、ぴーるなの確率を確認できる。 |
| 4 | **次の機能を選ぶ**。候補は決定済みの魔法ドロップ内訳の重み付け。上級職スキル、素材・合成、周回の追加機能は下の一覧をもとに検討する。 | 着手する機能ごとに設計と既存セーブへの影響を決める。重み付けに着手する場合は全体のドロップ率と当選後の内訳を別々に検証する。 |

順序は提案段階。既存セーブや戦績を元に戻しにくい変更では、着手前に移行方針と復旧方法を確認する。

## 4. 新しい開発依頼を受けたときのルール

1. 直近の指示が表の仮値と矛盾したら、新しい指示を優先する。
2. 決定済み仕様は**「確定」**、試行用に置いた数値は**「暫定」**、提案止まりは**「構想」**と区別する。
3. 実装前に関連文書と `index.html` を確認。新機能を作ったらこの表と対応する台帳を変更する。
4. 仕様が既存セーブに触れる場合、ユーザーデータ維持を最優先。
5. 決定済みの実装を台帳へ反映する。未実装の構想はユーザーの合意なく勝手に実装しない。
